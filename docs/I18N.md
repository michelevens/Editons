# Interface languages (English, French, Haitian Creole)

The app's own words — menus, buttons, messages, validation, the main
emails — can be read in English, French or Haitian Creole. A manuscript is
never translated: it is the author's text, in whatever language they write.

Decision record: `docs/DECISIONS.md`, "ADR-00XX — Interface languages".

## How a language is chosen

1. The account's stored choice (`users.locale`).
2. Signed out: the one picked on the sign-in page this session.
3. Otherwise the browser's `Accept-Language` (`fr-CA,fr;q=0.9` → French,
   `ht-HT` → Kreyòl, anything else → English). An account that has never
   had one stores this on its first visit, so it stays put across devices.

The switcher is in the account menu (under Appearance) and at the foot of
every sign-in page. `PUT /locale {locale}` stores it.

`<html lang>`, validation messages, the sign-in errors, dates and numbers
(`Intl`) and the emails to that account all follow. An invitation to
somebody without an account is written in the inviter's language.

## The catalogues

`api/lang/en.json`, `fr.json`, `ht.json` — one file per language, shared by
Laravel and React. Two kinds of key:

| Kind | Example | Used by | Parameters |
|---|---|---|---|
| Interface key | `"nav.books": "My Books"` | `t()` in React, `Locales::t()` in PHP | `{name}`, ICU plurals |
| Sentence key | `"Reset password": "Réinitialiser le mot de passe"` | `__()` in emails | `:name` (Laravel) |

Interface keys live in all three files; `en.json` holds the English exactly
as the screens said it before translation. Sentence keys are only in
`fr.json` and `ht.json`: the English is the key itself.

Laravel's own messages are PHP files: `lang/{fr,ht}/validation.php`,
`auth.php`, `passwords.php`, `pagination.php`.

Each JSON file starts with `_meta` (language and review status). Kreyòl is
`"status": "draft — needs native review"`.

### Message syntax (interface keys)

```
"menu.credits_left": "{credits} AI credits left"
"menu.active_books": "{count, plural, one {# active book} other {# active books}}"
"kind": "{format, select, pdf {PDF} other {file}}"
```

`#` in a plural branch is the number. `=0 {…}` matches exactly. French
"one" covers 0 and 1; Kreyòl nouns do not take a plural, so its catalogue
usually writes a single form (`"{count} liv aktif"`). A missing parameter
is left visible as `{name}` so it shows up in review.

## Adding a string

1. Pick a key: `area.what` in lower snake case (`shelf.new_book`). Never
   start it with `auth.`, `passwords.`, `pagination.` or `validation.`
   (those are Laravel's files; a test refuses them).
2. In React:

   ```jsx
   import { useI18n } from '@/i18n';

   const { t, formatNumber, formatDate } = useI18n();
   <button>{t('shelf.new_book')}</button>
   <p>{t('shelf.summary', { count: n, words: formatNumber(words) })}</p>
   ```

   Outside a component (a toast from a callback), `import { t } from '@/i18n'`.
   For lists of items defined in a constant, give each item
   `tKey: 'area.key'` and render `t(item.tKey)`: the static scan reads
   `t('…')` and `tKey: '…'` literals.
3. Add the key to `en.json` (the English, verbatim), `fr.json` and `ht.json`.
   `php artisan test --filter=Catalogue` fails until all three agree, and
   names any key the JSX uses that `en.json` lacks.
4. In PHP: `App\I18n\Locales::t('key', ['name' => …])` for interface keys,
   `__('An English sentence with :name')` for email copy (then add the
   sentence to `fr.json` and `ht.json`).

Numbers, money and dates: `formatNumber`, `formatMoney(cents, currency)`,
`formatDate(value, options)` from `useI18n()`. English passes no locale, as
the app always did; Kreyòl dates use the catalogue's month names
(`date.months`, `date.weekdays`) over Haiti's French layout (`fr-HT`).

## French typography

Narrow no-break space before `; ! ?`, no-break space before `:` and inside
« ». The generator applied them; when editing by hand, type them (or ask for
the file to be re-normalised).

## Reviewer corrections

`docs/i18n/ht-review.csv` and `docs/i18n/fr-review.csv` list every key with
its English, the current translation, and the screen it appears on. A
reviewer fills the **correction** column (blank = fine) and sends the file
back; a developer copies the corrections into `ht.json` / `fr.json` and runs
the catalogue tests. For Kreyòl, follow the standard orthography (IPN /
Akademi Kreyòl Ayisyen): `liv`, `chapit`, `anrejistre`, `pibliye`. When the
review is done, change `_meta.status` in `ht.json`.

Regenerating the CSVs after edits: one row per key, same columns; the
order follows the JSON.

## What is translated

- **Done:** sign-in pages and their layout; header, top navigation, account
  menu (with the language switch), the phone tab bar and More sheet, the
  book sidebar, search palette, shortcut sheet (every shortcut and the
  browser's reserved keys), dialogs' close buttons, notices; shelf (filters,
  toolbar, cards, table headers, empty states, new-book form); book
  overview; editor toolbar, autosave status, status bar, version history and
  editor notices; validation, sign-in and password messages; the
  invitation, password reset, email verification, royalty statement and
  weekly digest emails and the email layout.
- **Not yet (English, falls back):** shelf bulk-action panels; the rest of
  the writing studio (binder actions, comments, research, notes); Export &
  Publish, Cover Studio, Design & Layout; AI Editor, sales, partner
  dashboard, settings, inbox; the other emails; text the server sends
  ready-made (book type names and blurbs, the overview checklist, "2 hours
  ago").
- **Never:** manuscript content; the admin console (staff screens stay in
  English); partner pages keep their own page language
  (`PartnerPageView.jsx`, chosen by the partner, not the reader).
